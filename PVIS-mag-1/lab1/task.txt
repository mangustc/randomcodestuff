Практическое задание №1 Реализация многопоточных вычислений на
CPU
Написать программу на одном из языков программирования (С/ C++, C#, Java,
Python, Golang) с использованием инструментов многопоточной обработки на
базе CPU.
Содержание отчета.
1. Титульный лист
2. Задача по полученному варианту.
(если последняя цифра дня рождения 0 или 5: вариант 1;
если последняя цифра дня рождения 1 или 6: вариант 2;
если последняя цифра дня рождения 2 или 7: вариант 3;
если последняя цифра дня рождения 3 или 8: вариант 4;
если последняя цифра дня рождения 4 или 9: вариант 5
3. Листинг программ
4. Примеры входных и выходных файлов для программы
5. Визуализация процедуры решения задачи
6. Описание аппаратной базы, на которой выполнен тест (Операционная
система, характеристики CPU и оперативной памяти)
7. Описание результатов тестирования (время исполнения программного
кода при пятикратном запуске для каждой комбинации потоков/ процессов.
задач, среднее время исполнения кода, графики, показывающие
зависимости среднего времени от количества потоков/ процессов/ задач
для трёх тестовых файлов). Диаграммы размаха (boxplot), указывающие
время исполнения кода для разных файлов с разной длительностью.
8. Выводы

Для выполнения работы нужно выбрать три разных видео файла, каждый
содержит как минимум две сцены. Файлы должны отличаться размерами
кадра видео для того, чтобы оценить производительность алгоритма для
разных объёмов данных. Для каждого файла получить его фрагменты
продолжительностью 30, 60 и 120 секунд.

Вариант 1

Загрузить видеофайл в виде массива кадров. Задать число n – количество квантов
на которые разобьются оттенки цветового канала (столбцов гистограммы
распределения оттенков) (4<=n<=10).
Для каждого кадра получить гистограммы распределения цветовых оттенков.
Задать порог T – положительное число, являющееся критерием определения
незначительной разницы между кадрами видео. (Если расстояние между
векторами, выражающих частотное распределение цветовых оттенков
превышает порог T, то между кадрами есть разрыв в видео (два кадра
принадлежат разным сценам), в противном случае кадры принадлежат одной
сцене). На каждый кадр добавить число – номер сцены. Результат сохранить в
виде последовательности кадров с нумерацией сцены (видео, или набор
изображений).
Вариант 2
Загрузить видеофайл в виде массива кадров. Для каждого кадра получить его
матрицу интенсивности (градации серого) - усреднение трех матриц R, G и B:
I v =( Red ν + Green ν + Blue ν ) / 3,
где I v – интенсивность пикселя v, Red ν – значение красной компоненты пикселя
ν , Green ν – значение зелёной компоненты пикселя ν , Blue ν – значение синей
компоненты пикселя ν .
Получить пиксели исходя из значений матрицы интенсивности, которые входят
в первый квант (из четырех) интенсивности, т.е. чья интенсивность <64. Обвести
все такие пиксели на оригинальных кадрах границей из красных пикселей (255,
0, 0). Результат сохранить в виде последовательности кадров (видео, или набор
изображений).
Вариант 3
Загрузить видеофайл в виде массива кадров. Задать диапазоны цветовых
оттенков, регионы из которых будут искаться на кадрах (Например R=[150, 255],
G=[0, 50], B=[0, 50]).
Найти все пиксели, которые попадают в заданные диапазоны.
Задать размер S области в пикселях, который мы считаем значимым (например,
S=50 пикселей). Если есть на кадре области, состоящие из связанной области
размером не менее S, их нужно выделить (виртуально) прямоугольной рамкой.
Выполнить размытие с помощью свертки всех областей, находящихся
(https://annimon.com/article/3663
или
https://docs.gimp.org/2.8/ru/plug-inconvmatrix.html ) вне прямоугольных рамок. Результат сохранить в виде
последовательности кадров (видео, или набор изображений).

Вариант 4
Загрузить видеофайл в виде массива кадров. Задать n - число базовых оттенков
(8<=n<=32), которые будут использоваться для визуализации каждого кадра. Для
каждого из кадров выполнить кластеризацию алгоритмом K-Means цветовых
компонент пикселей на n -кластеров. Заменить цвета каждого пикселя цветовыми
компонентами центроида кластера, к которому принадлежит пиксель. Результат
сохранить в виде последовательности кадров (видео, или набор изображений).
Вариант 5
Загрузить видеофайл в виде массива кадров. Задать n – шаг, определяющий какие
кадры мы будем сравнивать (1<=n<=6). Если n=1, то сравниваем соседние кадры
1-2, 2-3, 3-4 и т.д., если n=2, то 1-3, 2-4, 3-5 и т.д. Выполнить вычитание матриц
цветовых компонент указанных кадров, исходя из шага n. Если длина вектора
разности меньше заданного порога T (величину подберите самостоятельно), то
мы будем считать, что компоненты пикселя изменились значительно, в
противном случае считаем, что пиксель изменился незначительно. Выбрать все
пиксели, цветовые компоненты которых изменились значительно и из этой
группы выбрать 10% пикселей с наиболее существенным изменением цветовых
оттенков. Выделить такие группы пикселей красной границей (255,0,0).
Результат сохранить в виде последовательности кадров (видео, или набор
изображений).
